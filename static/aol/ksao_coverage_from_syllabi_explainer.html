What this diagram shows

The repository’s Syllabus-to-O*NET–style path gives similarities (e.g. cosine between embedded learning-objective text and O*NET task lines). A percentage of Knowledge, Skills, or Abilities “covered” is not a single built-in field: it is a derived metric after you fix (1) how tasks link to K/S/A, (2) a similarity cutoff, and (3) what counts as the denominator (full O*NET lists vs occupation-important subsets — e.g. HR Specialist 13-1071.00 once your committee approves that target).

  • Repo touchpoints: semantic_similarity_mapper.py, compare_lo_onet_mapping_methods.py, docs/Syllabus_Occupation_KSAO_Stack.md, optional occupation_ksao_layer.py (O*NET Web Services reference profile).
  • Separate path: lo_task_ksao_mapper.py counts inferred K/S/A per LO from linked tasks; that is a count, not automatically “% of 33 knowledges.”

1. End-to-end data flow

From concentration syllabi to committee-facing percentages (conceptual).

flowchart TD
  subgraph inputs [Inputs]
    SYL[HR concentration syllabi]
    LO[Learning objectives extracted]
    ONETT[O*NET task statement corpus]
    ONETX[Optional task to K S A crosswalk tables]
    REF[Optional target SOC reference e.g. 13-1071 HR Specialist]
  end

  SYL --> LO
  LO --> SEG[Optional sentence split and boilerplate filter]
  SEG --> EMB[Embed LO text SBERT style]
  ONETT --> EMBT[Embed task lines]
  EMB --> SIM[Cosine similarity each LO span vs each task]
  EMBT --> SIM
  SIM --> POOL[Pool or top k tasks per LO]
  POOL --> ROLL[Per task aggregate max or mean similarity across LOs]
  ROLL --> LINK[Map tasks to Knowledge Skill Ability elements]
  ONETX --> LINK
  LINK --> ELEM[Per K S A element take max similarity over linked tasks]
  subgraph policy [Policy layer you define]
    TAU[Cutoff tau on similarity]
    DEN[Denominator full taxonomy vs SOC important subset from REF]
  end
  REF --> DEN
  ELEM --> TAU
  TAU --> COUNT[Count elements at or above tau]
  DEN --> PCT[Percent K percent S percent A]
  COUNT --> PCT
  PCT --> OUT[Tables charts gap narrative for governance]

Implementation detail: the “task → K/S/A” step may use official O*NET relational files or occupation-level endpoints; the diagram is logic, not a single script name.

2. Numerator and denominator

Why two committees can get different “%K” from the same syllabi: they chose different rules.

flowchart LR
  subgraph N [Numerator]
    A[For each K S A element]
    B[Strength equals max similarity across concentration LOs and linked tasks]
    C[Met if strength is at least tau]
    A --> B --> C
  end
  subgraph D [Denominator]
    E[Option A: all elements in category]
    F[Option B: elements occupation rates important for approved SOC]
    E --- G[Pick one and document]
    F --- G
  end
  C --> R[Divide met count by denominator count]
  G --> R
  R --> H[Report with footnote on tau SOC and task pool]

HR Specialist approval means committing to use 13-1071.00 (alone or blended) when defining Option B and when interpreting gaps.

3. Where ETS fits (parallel track)

Exam performance does not replace the similarity pipeline; it answers a different question.

  end
